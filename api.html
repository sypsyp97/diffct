API Reference¶

High-level Projector¶

class diffct.Projector(trajectory, volume_shape, detector_shape, *, beam='cone', detector_spacing=1.0, voxel_spacing=1.0, devices=None, distributed=False, process_group=None, detector_surface=None, volume_chunk_shape=None, view_chunk_size=None, detector_chunk_shape=None, schedule='auto', partition='views', backend='auto', precision='fast', partition_grid=None, native_volume_layout=False)[source]¶

Project floating tensors along parallel, fan, cone, or parallel3d trajectories.

A parallel trajectory is (ray_dir, det_origin, det_u) and a fan trajectory is (src_pos, det_center, det_u); each component has shape (views, 2). A cone trajectory is (src_pos, det_center, det_u, det_v) with components shaped (views, 3). A parallel3d trajectory is (ray_dir, det_center, det_u, det_v) with the same 3D component shapes; its infinite ray lines pass through detector pixels. Direction axes are unit vectors; parallel ray_dir and det_u and 3D detector det_u and det_v are orthogonal. Parallel3d rays can be oblique but must not be tangent to the detector plane. If no trajectory tensor requires gradients, the projector clones the geometry. Otherwise it keeps references, reads the current values at every call, and returns gradients for those tensors. Live default frames are checked at construction; overrides are checked on each call. project, backproject, __call__ and their *_into variants accept a keyword-only trajectory replacing all frames for that call. It must retain the constructor’s beam and view count; it is validated and snapshotted independently without replacing the default frames. Rebuild computed trajectories from trainable leaves on each optimization step. Second derivatives are available for volumes and sinograms, not for the geometry.

detector_surface(u, v) optionally supplies local (u, v, n) offsets for every pixel. It receives centred physical float64 grids on CPU and returns a floating-point tensor shaped (*detector_shape, 3) or (views, *detector_shape, 3). 3D normals are cross(det_u, det_v); 2D normals are (det_u_y, -det_u_x) with zero middle offsets. Offsets can be on CPU or CUDA in full-volume and streamed execution. World points expand on each compute device after view sharding. Native execution preserves the composition’s dtype promotion before converting complete coordinates to float32. The PyTorch backend uses the selected precision. The callback is sampled and validated on every call, with first-order gradients for captured PyTorch parameters. Omitting it preserves the flat detector.

ParameterizedSurface(sampler, parameters) instead samples only the selected global view IDs and detector rectangle. Its explicit parameters and trajectory values are snapshotted once per call, with batch-local first-order parameter gradients. detector_chunk_shape bounds pixel rectangles; their physical origins remain those of the full detector.

Volumes use (H, W) for parallel and fan beams and (D, H, W) for cone and parallel3d beams. Sinograms use (views, detectors) or (views, U, V). Any leading batch/channel dimensions are preserved. voxel_spacing is a positive scalar or a tuple in volume tensor order: (y, x) or (z, y, x). Physical coordinates retain the centred global volume frame. Results stay on the input device. precision="fast" and "float32" return float32; "float64" computes geometry, ray lengths and accumulations in float64. The selected backend, precision and dtype are public metadata.

backend="auto" selects the native "numba" backend for NVIDIA CUDA, fast precision and scalar voxel spacing, except for hybrid partitions. Other configurations use portable "torch" execution on the input’s CPU or supported PyTorch accelerator. Explicit "numba" requires a compatible native configuration. Parallel3d uses torch; explicitly selecting numba for it raises an error. Data torch.func transforms use portable operations while preserving selected metadata.

Native CPU inputs stream spatial tiles and view batches through CUDA. Native CUDA inputs retain the full-volume path when its additional working set fits every device; otherwise they stream too. volume_chunk_shape sets explicit spatial limits in tensor order; view_chunk_size sets an explicit view limit. Either forces native streaming. Native automatic sizing uses live free memory, reusable allocator cache and the observable per-process fraction ceiling, retaining 25% headroom. Automatic sizing compares fitting first-axis slabs and Cartesian blocks; view batches are at most 32 and shrink if needed. Older PyTorch without a public fraction getter cannot account for that ceiling. Concurrent external allocations can still cause an allocation error.

For the native backend, schedule="auto" selects spatial, view or bounded two-tile window order using estimated full-workload time from short native pilots, with estimated copy bytes breaking ties. The same orders can be requested with "spatial", "views" or "window"; capacity may require a serial spatial fallback. Streaming uses distinct upload, compute and download streams and two reusable host slots capped at 8 MiB each. Store reads and completed output drains are fragmented independently of the resident GPU tile size. last_execution_stats reports actual copy payloads, native launches/layouts, planned capacity and pilot metadata; it is None before execution, after errors, and on the uninstrumented native full-CUDA path. Portable execution reports actual ray/tile pairs, store I/O, transfers and collective payloads, with conservative automatic chunks targeting 8 MiB work arrays. Explicit chunk hints take priority. Reports and selection caches retain metadata.

native_volume_layout=True makes native full-CUDA cone backprojections of unbatched inputs on a flat detector return (D, H, W) tensors with the kernels’ (W, H, D)-contiguous strides instead of contiguous copies; native projections accept such tensors without a copy. An iterative solver that keeps its volumes in this layout then avoids two whole-volume copies per normal-operator application on one device. The layout does not change the operator. Results from several local devices, curved detectors, batched inputs, streamed execution and the PyTorch backend still involve copies.

Full host volumes/sinograms stay on CPU; streamed native CUDA buffers are bounded by the chosen tile and view batch. Caller-owned CUDA data/results and CUDA work inside a supplied callback are outside this memory bound. Native local devices launch their view batches concurrently, but each device receives every owned volume tile, so host transfers limit the speedup. Local devices split views in list order. partition="views" returns rank-local projections and replicated backprojections. partition="space" assigns balanced first-axis slabs and returns replicated projections and owned backprojections. partition="hybrid" combines both with partition_grid=(view_ranks, space_ranks) and parent-group rank view_rank * space_world_size + space_rank. global_volume_shape is the constructor shape; volume_slice identifies the owned global slab, and volume_shape and local_volume_shape give its required tensor shape. Empty slabs are valid. Physical coordinates retain the global volume frame. For replicated outputs, count the loss once globally or divide each rank’s projection loss by space_world_size or backprojection loss by view_world_size. Geometry gradients already SUM over all parent ranks; do not apply an additional DDP reduction to them. Space ranks participate in backward even when their local input and geometry require no gradients.

backproject(sinogram, *, trajectory=None)[source]¶

Apply the matched adjoint to a tensor ending in projection_shape.

Cone sinograms use (views, U, V) order after any leading batch/channel dimensions. The result preserves those dimensions, uses selected precision and stays on sinogram.device. View ranks SUM bounded volume contributions; spatial ranks return only the owned volume_slice. Divide replicated losses by view_world_size.

property process_group¶

Process group of a distributed operator, or None for the default group.

Pass it as group= to collectives that combine per-rank results of this operator, so they use the same ranks as the operator.

project(volume, *, trajectory=None)[source]¶

Project a floating tensor ending in the owned volume_shape.

Leading batch/channel dimensions are preserved ahead of projection_shape. The result has the selected precision and stays on volume.device. View partitions own contiguous view slices; spatial ranks SUM their ray contributions and replicate the result. Portable execution supports CPU and PyTorch accelerator tensors; native execution uses NVIDIA CUDA and streams CPU data when needed.

project_into(volume, output, *, trajectory=None)[source]¶

Numerically project into supplied output matching self.dtype.

Returns output; no complete result is allocated. Direct tensors requiring autograd must be detached or used under torch.no_grad(). Known overlapping/read-only outputs are rejected before execution.

Projector takes trajectory tensors as described in Trajectories and Geometry. For multiple GPUs and nodes, see Multiple GPUs and Nodes. Each operation also accepts trajectory=... to replace the full trajectory for that call, preserving its view count and the constructor default.

detector_surface defines native pixel positions for both projection and matched backprojection. See Parameterized detector surfaces for its coordinate and shape contract, and Examples for a runnable cylindrical detector.

Native CPU data uses streamed CUDA execution; backend="torch" computes on its PyTorch device. precision selects fast FP32 or strict FP32/FP64. Leading batch/channel axes and per-axis voxel spacing are supported; see Precision, training and reconstruction. volume_chunk_shape, view_chunk_size and detector_chunk_shape specify optional limits; schedule allows operation-specific comparisons. partition="space" assigns rank-local volume slabs. See Large Volumes and Chunked Execution for memory, storage, geometry and autograd requirements, and Multiple GPUs and Nodes for ownership.

class diffct.ParameterizedSurface(sampler, parameters=())[source]¶

Sample local detector offsets from global CPU pixel/view coordinates.

sampler(u, v, view_indices, *parameters) returns shared or per-view (..., 3) offsets on CPU or CUDA. Parameters are explicit finite floating tensors; other geometry configuration must be immutable. Projector snapshots the sampler reference and parameter values per invocation. Snapshot storage scales with parameter sizes, and the sampler’s own allocations remain caller-controlled.

project_into and backproject_into use caller-owned numerical outputs. ParameterizedSurface exposes mutable geometry as explicit tensor parameters and samples bounded global view/pixel rectangles. Legacy two-argument surface callbacks remain available. See Parameterized detector surfaces.

Low-level Functions¶

These autograd.Function wrappers take explicit trajectory tensors. Use the forward signature as the argument order for .apply(...). For new code, prefer Projector, which checks inputs and manages devices.

class diffct.ParallelProjectorFunction(*args, **kwargs)[source]¶

Bases: Function

Summary¶

PyTorch autograd function for differentiable 2D parallel beam forward projection.

Notes

Provides a differentiable interface to the CUDA-accelerated Siddon ray-tracing method with a cell-constant image basis for parallel beam CT geometry. The forward pass computes the sinogram from a 2D image using parallel beam geometry. The backward pass computes gradients using the adjoint backprojection operation. Requires NVIDIA CUDA hardware. Geometry tensors are moved to the image’s device; execution uses float32.

Examples

>>> import torch
>>> from diffct import ParallelProjectorFunction, circular_trajectory_2d_parallel
>>>
>>> image = torch.randn(128, 128, device='cuda', requires_grad=True)
>>> ray_dir, det_origin, det_u_vec = circular_trajectory_2d_parallel(180, device='cuda')
>>> sinogram = ParallelProjectorFunction.apply(image, ray_dir, det_origin, det_u_vec, 192, 1.0)
>>> sinogram.sum().backward()
>>> image.grad.shape
torch.Size([128, 128])

Analytical Reconstruction Helpers¶

These helpers build the pre-weights, angular weights, filter and weighted backprojection of an analytical FBP or FDK pipeline. The weighted backprojection helpers support sinogram autograd with dedicated transpose kernels, including higher derivatives. They use fixed geometry and reject geometry/isocenter gradients. The returned images are already scaled. See Differentiable analytical reconstruction for complete APIs and learnable filter/weight examples.

Analytical FBP and FDK assume a flat detector and an acquisition model. These helpers do not accept detector_surface. Native curved data must be resampled along matching rays onto a covered virtual flat detector before using these flat-detector helpers; resampling adds interpolation error. The native Projector forward/adjoint pair needs no such conversion. A non-circular trajectory does not make the result exact. The helpers accept the same per-view (src_pos, det_center, det_u[, det_v]) arrays as Projector.

Fan and cone backprojection accept a keyword-only isocenter vector in physical units. With None (default), it is estimated from the detector normals. Give it explicitly for non-circular or ambiguous geometry, including a single view. The three weighted backprojection helpers need at least two detector bins along each interpolated axis, including the cone detector’s v axis.

diffct.analytical.angular_integration_weights(angles, redundant_full_scan=True)[source]¶

Trapezoidal per-view integration weights for the analytical FBP/FDK sum.

For a full 2*pi scan, each redundant ray is sampled twice so the classical FBP/FDK formula carries a 1/2 redundancy factor. When redundant_full_scan=True (the default) this factor is baked into the returned weights: they sum to pi over a uniform full scan, which is exactly what a voxel-driven gather backprojector with the (sid/U)^2 weight needs to produce a unit-amplitude reconstruction.

Short scans retain their actual angular range; the Parker window handles their redundancy at the sinogram-filtering stage. Leave redundant_full_scan=True for automatic fan/cone scan classification. Setting it to False explicitly disables the full-turn 1/2 factor. Parker and angular quadrature share the same periodic-scan decision. FP16 and BF16 angles are promoted to FP32; FP64 angles retain their precision.

diffct.analytical.fan_cosine_weights(num_detectors, detector_spacing, sdd, detector_offset=0.0, device=None, dtype=torch.float32)[source]¶

Per-detector-cell cos(gamma) weight for fan-beam FBP.

cos(gamma) = sdd / sqrt(sdd^2 + u^2) where u is the in-plane detector coordinate. Multiplying the sinogram by this weight before the ramp filter compensates for the extra path length that off- principal-ray fans traverse.

diffct.analytical.parker_weights(angles, num_detectors, detector_spacing, sdd, detector_offset=0.0)[source]¶

Parker redundancy weights for a circular fan-beam short scan.

The formula follows Parker (1982): each ray at view beta and fan angle gamma is weighted by a smooth window that guarantees every ray contributes exactly once when integrated over the scan. For a full 2*pi scan this returns a constant 1 tensor (the usual redundancy 1/2 factor lives in angular_integration_weights instead).

Only meaningful for circular (fan-shaped) trajectories — when using non-circular trajectories you typically want either a constant weight (full-coverage) or a custom redundancy scheme. FP16 and BF16 angles are promoted to FP32; FP64 angles retain their precision.

diffct.analytical.ramp_filter_1d(sinogram_tensor, dim=-1, sample_spacing=1.0, pad_factor=1, window=None, use_rfft=True)[source]¶

Apply a finite discrete Ram-Lak filter along dim using FFT.

The angular-frequency impulse response is h[0] = pi/2, h[k] = -2/(pi*k**2) for odd k, and zero for nonzero even k (Kak and Slaney, chapter 3, equation 61, scaled by 2*pi). Transforming this finite kernel preserves its small positive DC response and avoids the low-frequency bias of directly sampling abs(omega). pad_factor >= 2 gives linear convolution over the retained samples for an unwindowed filter.

Parameters:

  • sinogram_tensor (torch.Tensor) – Real-valued sinogram tensor.

  • dim (int, optional) – Axis along which to filter. Default -1.

  • sample_spacing (float, optional) – Physical spacing between detector samples along dim. The continuous ramp filter has units of 1/length, so the FFT output is rescaled by 1 / sample_spacing to respect physical units.

  • pad_factor (int, optional) – Zero-pad the signal to pad_factor * N along dim before the FFT to suppress circular-convolution wrap-around artifacts.

  • window (str or None, optional) – Frequency-domain apodization: None / "ram-lak" (unwindowed), "hann", "hamming", "cosine", or "shepp-logan".

  • use_rfft (bool, optional) – Use the real-valued FFT path when True (default).

diffct.analytical.parallel_weighted_backproject(sinogram, ray_dir, det_origin, det_u_vec, detector_spacing, H, W, voxel_spacing=1.0)[source]¶

Voxel-driven parallel-beam FBP backprojection with analytical constant.

Runs the dedicated parallel-beam FBP gather kernel (one thread per output pixel, linear interpolation of the filtered sinogram, no distance weighting because parallel beam has no source) and multiplies by 1 / (2 * pi) so a unit-density disk reconstructs to amplitude 1.

Assumes the input sinogram has already been ramp-filtered with ramp_filter_1d and weighted by angular_integration_weights.

diffct.analytical.fan_weighted_backproject(sinogram, src_pos, det_center, det_u_vec, detector_spacing, H, W, voxel_spacing=1.0, *, isocenter=None)[source]¶

Voxel-driven fan-beam FBP backprojection with analytical constant.

Runs the dedicated fan-beam FBP gather kernel (one thread per output pixel, (sid_n/U_n)^2 distance weighting, linear interpolation of the filtered sinogram), applying the analytical factor sdd_n / (2 * pi * sid_n) to each view so a unit-density disk reconstructs to amplitude 1. Both distances are measured in the detector-normal direction per view, so the helper reduces to the classical sdd/(2*pi*sid) on a circular orbit. isocenter is a physical coordinate pair; by default it is inferred from the source lines along detector normals. Supply it explicitly for an ambiguous or non-circular acquisition. Analytical FBP remains acquisition-specific.

diffct.analytical.cone_weighted_backproject(sinogram, src_pos, det_center, det_u_vec, det_v_vec, D, H, W, du, dv, voxel_spacing=1.0, *, isocenter=None)[source]¶

Voxel-driven cone-beam FDK backprojection with analytical constant.

Runs the dedicated cone-beam FDK gather kernel (one thread per output voxel, (sid_n/U_n)^2 distance weighting, bilinear interpolation of the filtered sinogram), applying sdd_n/(2*pi*sid_n) to each view so a unit-density sphere reconstructs to amplitude 1. Both distances are measured in the per-view detector-normal direction, so the helper reduces to the classical sdd/(2*pi*sid) on a circular orbit. isocenter is a physical coordinate triple, inferred from source lines along detector normals by default. Supply it explicitly for an ambiguous or non-circular acquisition. FDK remains an approximation outside its circular-acquisition assumptions.

diffct.reconstruction.helical_view_weights(angles, source_z, slice_z)[source]¶

Return (slices,views) weights for complete slice-centered turns.

angles are strictly monotone, unwrapped radians; source_z is the corresponding strictly monotone source height, with at least two samples. slice_z holds physical slice centers. Reversed acquisitions are valid. Interpolate the angle at each height, then integrate angular sample cells over the centered 2*pi interval. Weights include the half redundancy factor and sum to pi. Missing coverage raises instead of renormalizing. These acquisition coordinates are fixed; learn replacement weights instead.

Gather filtered cone data using replaceable (D,views) weights.

sinogram is a filtered CUDA (views,U,V) tensor. view_weights includes angular quadrature and redundancy and is applied AFTER filtering. Ramp Filter Options¶

ramp_filter_1d is the filter used by the analytical examples. Its signature is:

ramp_filter_1d(sinogram_tensor, dim=-1, sample_spacing=1.0,
               pad_factor=1, window=None, use_rfft=True)
sample_spacing

Physical detector-cell spacing along dim, for example du for cone beam. The output is in physical units. Pass 1.0 to work in sample units.

pad_factor

Zero-pads the signal to pad_factor * N samples along dim. Use 2 for cone-beam FDK. Use 4 when objects lie close to the detector edge.

use_rfft

Uses the real FFT for real inputs. Set False only to force the complex FFT path.

The window argument selects a window applied to the Ram-Lak ramp:

window

Effect

None or "ram-lak"

No window. Sharpest, with the most noise.

"cosine"

Half-cosine roll-off.

"shepp-logan"

Sinc roll-off. Classical choice.

"hamming"

Milder than Hann.

"hann" or "hanning"

Strongest high-frequency suppression.
